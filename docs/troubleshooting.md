# Разрешения и решение проблем

## Команда не появилась в Finder

1. Откройте NewFile и нажмите «Включить расширение Finder…».
2. Включите NewFile в системных настройках расширений. На macOS 15.3.1 это
   **Основные → Объекты входа и расширения → Источники файлов**.
3. Закройте и снова откройте окно Finder. Проверьте обычную локальную папку.

Виртуальные разделы («Недавние», результаты поиска) и некоторые папки облачных
провайдеров могут не поддерживать расширение. Завершение приложения NewFile
не отключает расширение: оно запускает приложение при создании файла.

## Файл создаётся, но переименование не начинается

Для включения режима переименования нужно разрешение **Конфиденциальность
и безопасность → Универсальный доступ → NewFile**. Без него нажмите Return
после создания файла, чтобы начать переименование вручную.

После пересборки или установки другой версии macOS может сохранить разрешение
для старой подписи, хотя переключатель остаётся включённым:

1. Завершите NewFile.
2. Удалите только NewFile из списка «Универсальный доступ».
3. Нажмите «+» и добавьте ту копию, которую запускаете: например,
   `/Applications/NewFile.app` или `dist/NewFile.app` для локальной сборки.
4. Снова откройте приложение и проверьте создание из Finder.

Если запись не удаляется, сбросьте только разрешение NewFile:

```sh
tccutil reset Accessibility local.codex.newfile
```

Затем добавьте приложение заново. Другие приложения эта команда не затрагивает.
Не держите одновременно несколько запускаемых копий NewFile в разных папках.

При переключении активного окна автоматическое переименование может быть
пропущено: приложение проверяет выделение и адресует нажатие только Finder.
Созданный файл при этом сохраняется.

## macOS блокирует запуск скачанной сборки

Сборки CI имеют ad-hoc подпись, но не подпись Developer ID и не нотарификацию Apple.
Следуйте [официальной инструкции Apple](https://support.apple.com/102445)
для открытия приложения из известного источника. Другой вариант — собрать
приложение самостоятельно.

## Шаблон не создаёт документ нужного формата

NewFile создаёт пустой файл либо записывает текст UTF-8. Поддерживаются текстовые
шаблоны, например Markdown, Python, JSON и HTML. Изменение расширения на `.docx`
или `.xlsx` не превращает текст в документ Word или Excel.

## Проверка перед выпуском

Автоматические тесты не управляют Finder и не выдают системные разрешения.
На реальном Mac проверьте:

1. Создание из меню по свободному месту в папке и рядом с выбранным файлом.
2. Немедленное появление файла без диалога NewFile и ввод имени в Finder.
3. Подтверждение Return, отмену редактирования Escape и нумерацию совпадающих имён.
4. Создание с закрытым NewFile, смену шаблона, языка и названия команды.

Файловые операции используют атомарное создание без перезаписи существующих
файлов и ссылок. Полный доступ к диску не требуется; доступ к отдельным защищённым
папкам регулирует macOS.
