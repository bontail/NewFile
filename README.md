# NewFile

[![Build and Release](https://github.com/bontail/NewFile/actions/workflows/release.yml/badge.svg)](https://github.com/bontail/NewFile/actions/workflows/release.yml)
[![Latest release](https://img.shields.io/github/v/release/bontail/NewFile)](https://github.com/bontail/NewFile/releases/latest)

Создание файлов прямо из контекстного меню Finder.
Нативное приложение для **macOS 13 и новее · Apple Silicon**.

**Правый клик → «Создать файл» → введите имя.**

Файл появляется сразу, выделяется в Finder и переходит в режим переименования.
Отдельного окна ввода имени нет.

## Возможности

- Создание в открытой папке или рядом с выбранным файлом.
- Шаблоны: обычный текст, Markdown, Python и пустой файл; можно добавить свои.
- Подстановка даты, имени папки и имени файла в шаблоны.
- Собственное название команды Finder, без значка слева.
- Автоматическая нумерация при совпадении имён; существующие файлы не перезаписываются.
- 10 языков интерфейса, включая русский и английский.
- Работа локально: без учётной записи, сети и аналитики.

## Установка

1. Откройте [**Releases**](https://github.com/bontail/NewFile/releases/latest) и скачайте `NewFile-<версия>-macOS-arm64.zip`.
2. Распакуйте архив и переместите `NewFile.app` в **Программы**.
3. Запустите NewFile и нажмите **«Включить расширение Finder…»**. В настройках macOS включите NewFile.
4. Нажмите **«Разрешить переименование в Finder…»** и включите NewFile в **Конфиденциальность и безопасность → Универсальный доступ**.
5. В Finder нажмите правой кнопкой по свободному месту в обычной папке и выберите **«Создать файл»**.

Готовые сборки пока используют локальную подпись и **не нотарифицированы Apple**.
При блокировке запуска следуйте [инструкции Apple](https://support.apple.com/102445).
Сборку из исходников см. ниже. Mac с Intel текущей сборкой не поддерживается.

«Универсальный доступ» нужен для включения переименования в Finder. Без разрешения
файл всё равно создаётся и выделяется — нажмите **Return**, чтобы переименовать его вручную.
Пути к настройкам расширений могут различаться между версиями macOS.

## Использование

Откройте настройки NewFile сочетанием **⌘,**. Выберите шаблон по умолчанию:
он будет использоваться при создании из Finder. Настройки сохраняются автоматически.

| Подстановка | В имени файла | В содержимом |
| --- | --- | --- |
| `{date}` — текущая дата | Да | Да |
| `{folder}` — имя папки | Да | Да |
| `{name}` — исходное имя созданного файла с расширением | — | Да |

Например, имя `Заметка {date}.md` и содержимое `# {name}` создадут заметку с датой.
Формат даты по умолчанию — `yyyy-MM-dd`. Последующее переименование в Finder
не изменяет содержимое файла.

При совпадении имён появятся `Новый файл.txt`, `Новый файл 2.txt`, `Новый файл 3.txt`.
**Return** подтверждает новое имя; **Escape** завершает переименование, оставляя файл в папке.

Языки: русский, английский, немецкий, французский, испанский, итальянский,
португальский, украинский, упрощённый китайский и японский. Режим «Как в системе»
выбирает поддерживаемый язык из предпочтений macOS. Пользовательские шаблоны
и собственное название действия сохраняются при смене языка.

## Если что-то не работает

- **Команда отсутствует:** убедитесь, что включено расширение Finder, затем заново откройте окно Finder.
  Попробуйте обычную локальную папку: поиск, «Недавние» и некоторые облачные папки могут не поддерживаться.
- **Файл создаётся, но имя не редактируется:** проверьте разрешение «Универсальный доступ».
  После смены сборки может понадобиться удалить NewFile из списка разрешений и добавить текущую копию заново.
- **Нужно поставить команду первой:** положение команд расширений задаёт Finder.
  Встроенной настройки для переноса выше системных команд нет.

Подробности: [разрешения и решение проблем](docs/troubleshooting.md),
[положение команды в меню Finder](docs/finder-menu.md).

## Сборка из исходников

Нужны Mac с Apple Silicon и **Xcode Command Line Tools** либо полный Xcode.
Внешних зависимостей у приложения нет.

```sh
xcode-select --install  # если инструменты ещё не установлены
bash test.sh           # проверки файловых операций, настроек и переводов
bash build.sh          # dist/NewFile.app
```

Для архива с приложением, документацией и исходниками:

```sh
bash package.sh
```

Команда сама запускает тесты и собирает приложение в отдельной временной папке.
Результат: `release/NewFile-<версия>-macOS-arm64.zip` и файл `.zip.sha256`.
Она не заменяет `dist/NewFile.app` и не регистрирует временное расширение в Finder.

## CI и релизы

GitHub Actions запускает тесты, собирает приложение, проверяет подпись и сохраняет
архив при изменениях в `main`, в pull request и при ручном запуске.
После успешной сборки тега `vX.Y.Z` автоматически публикуется **GitHub Release**
с архивом и контрольной суммой SHA-256. Версия тега должна совпадать с файлом `VERSION`.

```sh
# Обновите VERSION, затем закоммитьте изменения и отправьте их в main.
git tag v3.1.0
git push origin v3.1.0
```

Для следующего выпуска укажите новую версию в `VERSION` и соответствующий новый тег.
Секреты для обычной сборки и публикации не требуются: используется `GITHUB_TOKEN`.
Это не заменяет подпись Developer ID и нотарификацию Apple.

Подробнее: [первый push, сборка и выпуск версий](docs/development.md).

## Как устроен проект

| Каталог | Содержимое |
| --- | --- |
| `Sources/` | Приложение, расширение Finder, шаблоны и переименование |
| `Resources/` | Переводы на 10 языков |
| `Config/` | Метаданные приложения, версия и права расширения |
| `Tests/` | Проверки файловых операций, настроек и переводов |
| `.github/workflows/` | Автоматическая сборка и публикация релизов |
| `Artwork/` | Исходник иконки и промпт генерации |

Для удаления выключите расширение, завершите NewFile и переместите приложение
в Корзину. Созданные файлы останутся на месте.
