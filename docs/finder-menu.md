# Положение команды в меню Finder

NewFile использует Finder Sync: передаёт Finder собственную команду,
а Finder определяет её положение относительно системных пунктов.
В настройках NewFile можно изменить текст команды; значка слева у неё нет.

## Можно ли поставить команду первой?

Подтверждённой обычной или скрытой настройки macOS для этого не найдено.
Перестановка собственных команд расширения не даёт управления всем меню.

- [Практически такой же вопрос на Stack Overflow](https://stackoverflow.com/questions/72732904/how-to-make-the-nsmenuitems-position-just-below-new-folder-item-in-findersync).
  В комментарии указано, что расположение определяет Finder; готового решения нет.
- [Объяснение разработчика FileUtils на Reddit](https://www.reddit.com/r/macapps/comments/1w4gg9b/comment/p7jo35k/).
  Он описывает вмешательство в процесс Finder как отдельный путь, требующий
  ослабления системной защиты и зависящий от версии macOS. NewFile этого не делает.

## Что делает NSServicesMinimumItemCountForContextSubmenu?

Этот параметр задаёт порог объединения команд в подменю «Службы».
Большой порог позволяет показывать службы непосредственно в контекстном меню.
Он не задаёт порядок строк и не влияет на Finder Sync — механизм NewFile.
Параметр описан в [руководстве Default Folder X](https://www.stclairsoft.com/DefaultFolderX/DefaultFolderXGuide.pdf).

## Отдельное меню по правому клику

Приложения, которые показывают собственное меню, могут сами задавать порядок
команд. Это меняет поведение правого клика, а не переставляет строки меню Finder.
В NewFile такого режима нет.

Например, [Ocomenu](https://github.com/piro0919/ocomenu) обрабатывает клик
по файлу или папке; свободное место оставляет обычному Finder. Поэтому этот
вариант не решает сценарий «правый клик по свободному месту → первая команда».
Возможности и совместимость сторонних утилит нужно проверять отдельно.
